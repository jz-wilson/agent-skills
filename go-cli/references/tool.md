Kong for parsing, `internal/` only when needed, testscript for end-to-end tests, golangci-lint v2, go-task once there are 4 or more tasks, goreleaser once binaries ship to people without Go.

## Layout

Start flat (go.dev/doc/modules/layout):

```
go.mod
main.go            # main() + run(ctx, args, stdout, stderr) + version fallback
cli.go             # Kong CLI struct, one XxxCmd struct per subcommand with a Run method
internal/<pkg>/    # only when logic outgrows package main or needs its own tests
testdata/*.txtar   # testscript end-to-end tests
main_test.go       # testscript wiring
.golangci.yml
.gitattributes     # * text=auto eol=lf, keeps .txtar and scripts LF on Windows
Taskfile.yml       # only at 4+ recurring tasks
.goreleaser.yaml   # only when shipping binaries
```

- **No `cmd/`** unless the repo builds more than one binary (then use `cmd/<name>/main.go`).
- **Never `pkg/`.** golang-standards/project-layout is not an official standard and says itself that `/pkg` "is not universally accepted"; `internal/` is the official way to keep packages private.
- No speculative `internal/app`, `internal/output` or `internal/config`. Create a package when there is code to put in it.

## Kong

The struct is the CLI: fields with `cmd:""` are subcommands, `arg:""` are positionals, everything else is a flag. Each command gets a `Run` method. Values bound with `kctx.Run(...)` and `kctx.BindTo(...)` are injected into its parameters by type.

**One command, no subcommands?** Put the flags, the `arg:""` positionals and the `Run` method on the root `CLI` struct itself. `kctx.Run(...)` calls it the same way. Add the `cmd:""` subcommand structs only when a second command appears.

Parse with `kong.New` + `parser.Parse(args)`, not `kong.Parse()`. The global version reads `os.Args` and calls `os.Exit` itself, which breaks rule 1.

- `kong.Writers(stdout, stderr)`: help goes to the injected stdout, and errors are yours to print.
- `kong.UsageOnError()`: a parse error also prints usage.
- Parse error → print `tool: <err>`, exit 2. `--help` exits 0 by itself (Kong calls its exit hook).
- Pass `context.Context` into commands with `kctx.BindTo(ctx, (*context.Context)(nil))`.
- Config files or env vars: use Kong's `env:"NAME"` tag first; only reach for `kong.Configuration(kong.JSON, paths...)` when a file is truly needed. No Viper.

### How it looks

Real output (WSL, Kong v1.16.1). This is the bar for a Tool-tier CLI: Kong's generated help, one-line errors prefixed with the tool name, data alone on stdout.

```
$ greeter --help
Usage: greeter <command> [flags]

A minimal Kong example.

Flags:
  -h, --help       Show context-sensitive help.
  -v, --verbose    Verbose logging to stderr.

Commands:
  greet <name> [flags]
    Greet someone.

  version [flags]
    Print the version.

Run "hello <command> --help" for more information on a command.

$ greeter greet --help
Usage: greeter greet <name> [flags]

Greet someone.

Arguments:
  <name>    Who to greet.

Flags:
  -h, --help       Show context-sensitive help.
  -v, --verbose    Verbose logging to stderr.

      --shout      Uppercase the greeting.
      --json       Print JSON instead of text.

$ greeter greet
greeter: expected "<name>"                 # exit 2

$ greeter greet world
hello, world

$ greeter greet --json --shout bob
{"greeting":"HELLO, BOB"}
```

For anything that takes more than a moment (network, many files), add the feedback layer from [ux.md](ux.md): the themed `🔵 info:` / `✅ ok:` / `🟡 warn:` / `❌ error:` lines, a spinner or progress bar, and tables for terminal output.

### Version

`version` stays `""` in source. goreleaser's default ldflags set `-X main.version={{.Version}}`. Without them (`go build`, `go install module@v1.2.3`), `buildVersion` falls back to the module version Go stamps into the binary, then to the VCS revision, then to `devel`. Verified: a goreleaser snapshot prints `0.0.0-SNAPSHOT-…`, and a local `go install .` in a tagged repo prints `v0.1.0+dirty`.

## Tests: testscript

End-to-end tests run the real binary in-process: argv, stdout, stderr and exit codes in one `.txtar` file per behavior.

`main_test.go`:

→ Read [`assets/tool/main_test.go`](../assets/tool/main_test.go) (15 lines; builds, tests and lints clean).

`testdata/greet.txtar`:

→ Read [`assets/tool/testdata/greet.txtar`](../assets/tool/testdata/greet.txtar) (21 lines; builds, tests and lints clean).

- `! exec` asserts a non-zero exit. To pin the exact code (2 vs 1), check it once by hand or with a Go test that calls `run`.
- Install the `testscript` CLI (`go install github.com/rogpeppe/go-internal/cmd/testscript@latest`) to run a single `.txtar` file ad hoc.
- Unit-test `internal/` packages with plain `go test` and table tests.
- **Network tests stay offline:** use `httptest.NewServer`/`NewTLSServer`, or certs made in the test with `x509.CreateCertificate` and a chosen `NotAfter`. For a raw listener, write `new(net.ListenConfig).Listen(ctx, "tcp", "127.0.0.1:0")`; plain `net.Listen` fails the `noctx` linter.
- **"Unreachable" tests need a short timeout flag** (`--timeout 1s`). In WSL, a connect to `127.0.0.1:1` hangs about 10 s instead of being refused, so don't rely on an instant refusal.

## Lint: golangci-lint v2

Install the binary (`curl -sSfL https://golangci-lint.run/install.sh | sh -s -- -b $(go env GOPATH)/bin v2.14.0`, or scoop on Windows). Don't use `go tool`: its own docs advise against it because tool dependencies get mixed into your module's.

`.golangci.yml`:

→ Read [`assets/tool/.golangci.yml`](../assets/tool/.golangci.yml) (32 lines; builds, tests and lints clean).

- `default: standard` is errcheck, govet, ineffassign, staticcheck and unused. Never `default: all`: wsl, varnamelen and exhaustruct are noise.
- The errcheck exclusion is for diagnostics written to stderr. Return the error from a write in a `Run` method (as `GreetCmd.Run` does) when it carries data.
- `defer f.Close()` on a **read-only** file: `//nolint:errcheck // read-only: a close error loses no data`. On a file you **wrote**, check `Close` and return its error. A failed close can mean lost data.
- Format with `golangci-lint fmt ./...`; check with `golangci-lint fmt --diff ./...`.
- `go tool` *is* fine for small pure-Go generators (stringer, mockgen): `go get -tool golang.org/x/tools/cmd/stringer`.

## Task runner: go-task, only at 4+ tasks

Below about 4 recurring tasks, the `go` commands are the interface. Don't add a runner. When you do, use go-task (cross-platform single binary; Make is a pain on Windows):

→ Read [`assets/tool/Taskfile.yml`](../assets/tool/Taskfile.yml) (16 lines; builds, tests and lints clean).

`task --list` shows only tasks with a `desc`; `task --list-all` shows every task. Verified with task v3.54.0: `task check` runs the format check, lint (which includes `go vet`) and `go test -race`, and fails on unformatted code.

## Release

- **Default:** `go install example.com/greeter@v1.2.3`. Tag `vX.Y.Z` and push. Nothing else needed.
- **Binaries for people without Go:** goreleaser v2. Start from `goreleaser init`, then trim to this (passes `goreleaser check` apart from needing a git remote):

→ Read [`assets/tool/.goreleaser.yaml`](../assets/tool/.goreleaser.yaml) (14 lines; builds, tests and lints clean).

  Run `goreleaser release --clean` from a tagged commit with `GITHUB_TOKEN` (or `GITEA_TOKEN`) set. Dry run with `goreleaser build --snapshot --clean --single-target`.
- **CI:** one job running `golangci/golangci-lint-action` with `version: v2.14.0`, plus `go test ./...`.
- Homebrew taps, Scoop manifests, signing and Docker images are out of scope until someone asks for them.
