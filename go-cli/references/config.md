For Tool-tier CLIs that need settings from env vars or a file, and tab completion. Kong only, no Viper. Read [tool.md](tool.md) first: this builds on its `run`/`newParser` shape.

Built, tested (table test + testscript) and linted (golangci-lint v2.14.0, config from tool.md, 0 issues) with Go 1.27.2 and Kong v1.16.1 in WSL on 2026-10-09.

## Precedence: flag > env var > config file > default

Reach for a file only when there are many settings or they are per-machine. Otherwise stop at `env:"TOOL_X"` + `default:"..."` (tool.md).

**Kong's own order is flag > config file > env var > default.** Kong applies `env:` and `default:` tags in `Reset`, as if they were defaults. Resolvers (config files) then fill any flag *not set on the command line*, so a file silently beats an env var. Verified: with `{"greeting":"hola"}` on disk and `GREETER_GREETING=bonjour`, plain `kong.Configuration` prints `hola`. That is backwards from what users expect (12-factor, git, docker, gh all put env above the file).

The fix is a root `BeforeResolve` hook (below). Resolvers run in order and the **last non-nil answer wins**, so load the `--config` file, then env vars, last.

### Loader choice (checked 2026-10-09)

| Option | Deps added | State |
|---|---|---|
| `kong.JSON` (ships in Kong) | none (stdlib `encoding/json`) | Maintained with Kong v1.16.1 |
| `github.com/alecthomas/kong-toml` v0.4.1 | `pelletier/go-toml` v1.9.5 (the old v1 line) + `alecthomas/errors`, `repr` | Released 2026-10-02, 5 stars |
| `github.com/alecthomas/kong-yaml` | a YAML library (go.mod not read) | Last release-relevant commit 2024-04-09 |

**Use `kong.JSON`.** Zero new dependencies, and the least-dependency rule decides it. Cost: no comments in the file. If users need comments, swap one line for `kongtoml.Loader` (kong-toml README: `kong.Configuration(kongtoml.Loader, path)`); nothing else changes. Don't add YAML.

JSON key mapping: the flag name, with `-` read as `_` or camelCase (`dry-run` matches `dry_run` or `dryRun`). A flag on a subcommand is looked up by its own name at the top level, so `{"greeting":"hola"}` configures `greeter greet --greeting`. Dotted keys nest.

### Config path

`os.UserConfigDir()` (verified with `go doc os UserConfigDir`): `$XDG_CONFIG_HOME` or `~/.config` on Linux, `%AppData%` on Windows, `~/Library/Application Support` on macOS. It errors when `$HOME` is unset; treat that as "no config file". Use `<dir>/<tool>/config.json`.

`kong.Configuration(loader, paths...)` semantics, from its source (`options.go`):

- Missing or unreadable (permission) path: skipped silently. A missing config file is fine.
- Exists but malformed: `kong.New` returns `<path>: <json error>`. `run` prints it and exits **1** (it is a setup error, not a usage error).
- `--config PATH` (explicit): a missing file is an error, exit **2**. The user named it, so skipping would hide a typo.

### Code

`cli.go` (config part; the greet command is a stand-in for yours):

```go
type CLI struct {
	Config string `short:"c" placeholder:"PATH" help:"Config file (JSON) read after the default one, so it wins over it."`

	Greet      GreetCmd         `cmd:"" help:"Greet someone."`
	Completion komplete.Command `cmd:"" help:"Print a shell completion script."`
}

type GreetCmd struct {
	Name     string `arg:"" help:"Who to greet."`
	Greeting string `env:"GREETER_GREETING" default:"hello" help:"Word to greet with."`
	Shout    bool   `env:"GREETER_SHOUT" help:"Uppercase the greeting."`
}

// BeforeResolve runs after parsing, before Kong fills flags nobody set on the command line.
// Kong's own order is flag > config file > env var > default, because env vars are applied
// as defaults. Resolvers run in order and the last non-nil answer wins, so loading --config
// and then the env vars here makes it flag > env var > config file > default.
// Flag values are not copied into the struct yet, so --config is read from the parse context.
func (*CLI) BeforeResolve(k *kong.Kong, ctx *kong.Context) error {
	for _, p := range ctx.Path {
		if p.Flag == nil || p.Flag.Name != "config" {
			continue
		}
		r, err := k.LoadConfig(ctx.FlagValue(p.Flag).(string))
		if err != nil {
			return err
		}
		ctx.AddResolver(r)
	}
	ctx.AddResolver(kong.ResolverFunc(func(_ *kong.Context, _ *kong.Path, flag *kong.Flag) (any, error) {
		for _, name := range flag.Envs {
			if v := os.Getenv(name); v != "" {
				return v, nil
			}
		}
		return nil, nil
	}))
	return nil
}

// defaultConfigPaths is <user config dir>/greeter/config.json.
// With no resolvable config dir (no $HOME) there is simply no config file.
func defaultConfigPaths() []string {
	dir, err := os.UserConfigDir()
	if err != nil {
		return nil
	}
	return []string{filepath.Join(dir, "greeter", "config.json")}
}
```

`main.go`, inside `run` (the rest is tool.md's shape):

```go
parser, err := kong.New(&cli,
	kong.Name("hello"),
	kong.Writers(stdout, stderr),
	kong.UsageOnError(),
	// Later paths win over earlier ones; a missing file is skipped, a malformed one is an error.
	kong.Configuration(kong.JSON, defaultConfigPaths()...),
)
if err != nil {
	fmt.Fprintf(stderr, "greeter: %v\n", err)
	return 1
}
```

Layering as built: default file (app-level resolver) < `--config` file < env resolver (both context-level, appended in that order) < command-line flag (never resolved at all).

Gotchas, all hit while building this:

- **`--config` is not in the struct yet inside `BeforeResolve`.** Kong copies parsed values to the struct in the Apply step, after Resolve. `c.Config` is still `""`. Read it with `ctx.FlagValue(flag)` from `ctx.Path`. (`kong.ConfigFlag` does this too, but it adds its resolver *after* any root hook, so the file would beat env again; hence the hand-written loop.)
- **The hook must be on the root struct, with `*kong.Kong, *kong.Context` parameters.** Kong injects hook arguments by type.
- **An empty env var counts as set** for the `env:` tag: `GREETER_SHOUT= greeter greet x` fails with `bool value must be true, 1, yes, false, 0 or no but got ""`. The hook above skips empty values, but the tag path does not. In tests, unset instead of `t.Setenv(k, "")`.
- `env:` tags stay on the fields even though the hook re-reads them: the tag is what puts `($GREETER_GREETING)` in `--help` and exposes `flag.Envs`.
- Secrets: env var or file mode 0600, never a flag (visible in `ps`). Tokens belong in Bitwarden/keyring, not a config file.

### Test: precedence table

`config_test.go`. `run` is called directly with temp config dirs, so no binary is built. One helper isolates the config dir on all three OSes:

```go
// isolateConfigHome points os.UserConfigDir at a temp dir on Linux, Windows and macOS
// and returns the path of the default config file.
func isolateConfigHome(t *testing.T) string {
	t.Helper()
	home := t.TempDir()
	t.Setenv("HOME", home)
	t.Setenv("XDG_CONFIG_HOME", filepath.Join(home, "xdg"))
	t.Setenv("AppData", filepath.Join(home, "appdata"))
	// Kong treats an empty variable as set, so unset rather than set to "".
	// t.Setenv registers the restore first, so the unset is undone afterwards.
	for _, k := range []string{"GREETER_GREETING", "GREETER_SHOUT"} {
		t.Setenv(k, "")
		if err := os.Unsetenv(k); err != nil {
			t.Fatal(err)
		}
	}
	dir, err := os.UserConfigDir()
	if err != nil {
		t.Fatal(err)
	}
	return filepath.Join(dir, "greeter", "config.json")
}

func TestPrecedence(t *testing.T) {
	tests := []struct {
		name string
		file string // content of the default config file; empty means no file
		env  string // GREETER_GREETING; empty means unset
		args []string
		want string
	}{
		{"default", "", "", []string{"greet", "ann"}, "hello, ann\n"},
		{"file beats default", `{"greeting":"hola"}`, "", []string{"greet", "ann"}, "hola, ann\n"},
		{"env beats file", `{"greeting":"hola"}`, "bonjour", []string{"greet", "ann"}, "bonjour, ann\n"},
		{"flag beats env", `{"greeting":"hola"}`, "bonjour", []string{"greet", "--greeting=ciao", "ann"}, "ciao, ann\n"},
		{"file sets a bool", `{"shout":true}`, "", []string{"greet", "ann"}, "HELLO, ANN\n"},
	}
	for _, tt := range tests {
		t.Run(tt.name, func(t *testing.T) {
			path := isolateConfigHome(t)
			if tt.file != "" {
				write(t, path, tt.file) // MkdirAll(0o750) + WriteFile(0o600)
			}
			if tt.env != "" {
				t.Setenv("GREETER_GREETING", tt.env)
			}
			var stdout, stderr bytes.Buffer
			if code := run(context.Background(), tt.args, &stdout, &stderr); code != 0 {
				t.Fatalf("exit %d, stderr: %s", code, stderr.String())
			}
			if got := stdout.String(); got != tt.want {
				t.Errorf("stdout = %q, want %q", got, tt.want)
			}
		})
	}
}
```

Two more tests in the same file, same pattern:

- `--config other.json` beats the default file, **and** `GREETER_GREETING` still beats `--config`.
- Error table: a malformed default file gives exit 1 and a message containing `config.json: `; `--config nope.json` gives exit 2 and names the file; stdout stays empty in both.

`go test` gives `ok example.com/greeter 0.030s`. Gosec G301 wants `0o750` for the config dir in tests.

## Shell completion

Kong has none built in. Every third-party option works the same way: the shell runs the program itself with `COMP_LINE` and `COMP_POINT` set (bash's `complete -C`), and the program prints candidates, one per line, then exits. The CLI must call the library **after `kong.New`, before `Parse`**.

### Options (checked 2026-10-09, GitHub API + proxy.golang.org)

| Library | Latest | Last commit | Shells | Runtime deps beyond Kong |
|---|---|---|---|---|
| `go.abhg.dev/komplete` (abhinav/komplete) | v0.1.0, 2024-10-05 | 2026-05-11 (dependency bumps) | bash, zsh, fish | `buildkite/shellwords` |
| `github.com/jotaen/kong-completion` | v0.0.14, 2026-04-30 | 2026-04-30 | bash, zsh, fish | `posener/complete` v1 (deprecated, per komplete's source notes), `riywo/loginshell`, `hashicorp/go-multierror` |
| `github.com/willabides/kongplete` | v0.2.0, 2021-01-13 | 2023-11 (pushed 2024-07) | bash, zsh, fish | `posener/complete` |
| `github.com/miekg/king` | v1.0.17, 2026-09-24 | 2026-09-24 | bash, zsh (fish "unfinished") | `gomarkdown`, `mmarkdown` (it also builds man pages); generates static files, not a runtime hook |

**None supports PowerShell.** Any of them would need a hand-written script for it; I did not build one.

**Recommendation: komplete.** Smallest dependency set (one small module), the engine is a from-scratch Kong walker that powers git-spice, and it ships a ready `Command` struct for the `completion` subcommand. kongplete is stale (2021) and kong-completion drags in the deprecated posener v1. The honest weak spot: komplete has not tagged since 2024, so you pin `v0.1.0` and its Kong requirement is older than yours (Go's resolution picks Kong v1.16.1 anyway; verified, tests pass). If it goes unmaintained, switch to jotaen/kong-completion: the call shape is the same, `Register(parser)` instead of `Run(parser)`.

```
go get go.abhg.dev/komplete@v0.1.0
```

Wire-up (from `main.go` and `cli.go` above):

```go
parser, err := kong.New(&cli /* ... options ... */)
// ...
komplete.Run(parser) // no-op unless COMP_LINE is set; then it prints candidates and exits 0

// in CLI:
Completion komplete.Command `cmd:"" help:"Print a shell completion script."`
```

`komplete.Command` takes an optional `<shell>` of `bash`, `zsh` or `fish`, and guesses from `$SHELL` when it is omitted. It prints a one-liner that points the shell back at the installed binary (`os.Executable()`), so completion works only once the binary is at its final path.

Mind the exit: `komplete.Run` finishes via `parser.Exit(0)`, which is `os.Exit` unless you set `kong.Exit`. That is fine in production and in testscript (separate process). In a plain `go test` that calls `run` it would end the test binary; test completion through testscript as below.

### Install, per shell

Put these in the tool's README and `--help` epilog. `greeter` must be on `$PATH` first.

| Shell | Once |
|---|---|
| bash | `echo 'source <(greeter completion bash)' >> ~/.bashrc` |
| zsh | `echo 'source <(greeter completion zsh)' >> ~/.zshrc` (the script runs `bashcompinit` itself) |
| fish | `greeter completion fish > ~/.config/fish/completions/greeter.fish` |
| PowerShell | Not supported by any Kong library. Say so; don't promise it. |

```
# the shell asks via COMP_LINE; the binary prints candidates, one per line.
# COMP_POINT is omitted on purpose: komplete then uses the end of the line, so
# the test survives renaming the command (a hardcoded cursor offset would not).
env COMP_LINE='greeter gr'
exec greeter
stdout '^greet$'
! stdout 'completion'

# flags complete after a dash
env COMP_LINE='greeter greet --sh'
exec greeter
stdout '^--shout$'

# without COMP_LINE it is a normal run
env COMP_LINE=
exec greeter completion bash
stdout 'complete -C .* greeter'
```

Known gaps, all observed:

- **No filename completion** for path flags such as `--config`: komplete registers `complete -C` without `-o default`, so bash offers nothing. Add a `predictor:"files"` tag with `komplete.WithPredictor` if a path flag matters (not built here); kong-completion falls back to the shell's default and does not have this gap.
- `greeter completion <TAB>` also yields one empty candidate, because the shell enum is declared `bash,zsh,fish,` (empty allowed). Harmless.
